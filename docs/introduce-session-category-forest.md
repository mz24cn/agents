# 会话分类森林：数百会话的导航、聚类与自动维护

> 玲珑 Agent Service 的会话数据随使用持续增长（当前 551 个）。会话分类森林是为它们自动维护的导航系统：单一数据文件 `chat_data/tree.json` 同时承载**主题、工作区、标签、终端、会话历史**五种检索入口。主题树由聚类 + LLM 命名产生，标签是人工多值标注，其余根按确定性事实组织，并与主题树保持严格的挂载一致性。实现集中在 `runtime/category_tree_builder.py`（构建/刷新）、`runtime/session_manager.py`（增量挂载）与 `runtime/label_store.py`（标签聚合），当前森林版本 TREE_VERSION=9。

---

## 一、为什么是森林而不是树

会话的检索意图天然是复数的："我上次解决过什么问题"按主题找，"这个目录里发生过哪些对话"按工作区找，"这个会话跑在哪台机器"按环境找，"上个月干了什么"按时间找。单一语义聚类树无法同时满足四类入口，也不应该满足。森林模型即：同一批会话挂到多个根下，每个根按自己的逻辑组织。

v9 森林五根（根 id 固定为 1/2/6/3/5）：

| 根 | 节点类型 | 组织逻辑 | 变化方式 |
|---|---|---|---|
| 主题 (1) | `category` | TF-IDF + KMeans 递归聚类，LLM 命名 | 仅重建 / 分类操作 |
| 工作区 (2) | `environment` → `workspace` | 按会话 `meta.workspace` 分目录，上层是执行环境层；目录节点下挂主题树的**按工作区筛选副本**，副本再按末级门槛做**分类合并** | 随事实增量补挂 |
| 标签 (6) | `label` | 会话携带 0..n 个标签，节点按会话数降序；标签来自 index.json 条目 `labels` | 随标签编辑同步（`set_session_labels`） |
| 终端 (3) | `terminal_environment` → `terminal_layer` | 环境层 = 会话 `meta.remote_env` ∪ `remote_envs.json` 注册表；子层用户自配置 | 注册表与用户配置驱动 |
| 会话历史 (5) | `month`（YYYYMM） | 按 `created_at` 分组倒序，月内按最近活动倒序 | 新会话即追加 |

除嵌套 talk_to 子会话（沿父会话继承分类，不单独参与聚类）外，每个会话恰好属于一个主题末级，同时出现在对应的工作区目录与月份节点下——主题、工作区、历史三根共享同一会话 id 集合。标签根是唯一的例外：它承载人工多值关系，一个会话可携带多个标签、也可以没有标签，不参与单分类不变量。

## 二、单分类不变量

每个会话在主题子树中最多属于一个末级分类。这条不变量是多分类实验后的结论：曾允许一个会话挂多个分类，541 会话规模下出现 61 个多分类会话、membership 边比会话多出 15%，"所属目录"菜单出现歧义，目录失去定位价值。

实现三处收口：

- 构建器 `validate()` 检测到重复 membership 即拒绝写出 tree.json；
- `attach_session_to_category()` 是**移动语义**——先挂入目标末级，再从其他末级移除，并剪除因此变空的分类及祖先；
- fork / talk_to 派生会话经 `inherit_categories()` 继承父会话的唯一分类。

## 三、聚类流水线（主题根）

`runtime/category_tree_builder.py` 是运行时模块：sklearn/numpy 经 `importlib` 动态导入，缺失时退化为纯 Python k-means，满足运行时目录零第三方依赖的静态检查。

**1. 文档装配与信号加权。** 每个会话的聚类文本按重复次数表达权重：

```
doc = 改动文件路径 ×16 + workspace ×3 + 标题 ×2 + 用户正文 ×2 + assistant 正文 ×1（截断）
```

改动文件取自该会话 file_journals manifest（每会话上限 60 条，绝对路径按 workspace 原分隔符风格拼接，Windows 反斜杠保留）；`meta.workspace` 缺失时回退到 manifest 中最常见 workspace。文件权重 16 是实测拐点：共享文件的会话对落入同末级的比例从 4.7% 升至 6.2%（仅两会话共享的文件对从 8% 升至 16%）；权重 ≥32 后退化为文件集合精确匹配，分支碎片化，指标反降。

**2. 切分与向量化。** 中文 2/3-gram 与英文标识符、路径段混合作词，TF-IDF + L2 归一化。嵌套 talk_to 会话与 system/tool 消息不参与，防内部代理会话污染语料。

**3. 节点内公共词抑制。** 节点内文档频率 >35% 的词在分裂前屏蔽（保底保留 40 个特征列），随后按行重新 L2 归一化。动机：同一节点下的会话天然共享领域词（agents、runtime 等），它们是共同背景而非区分信号；不屏蔽时 KMeans 只能沿噪声维度切刀，实测出现过 5 个"Agents××"并列分类。参数经 `SESSION_TREE_DF_MASK_RATIO` 可调。

**4. K 选择与递归分裂。** 候选 K 在区间内取样（每轮至多 5 点），silhouette 仅用于候选间相对择优，**不设绝对门槛**——本类会话语料的 cosine silhouette 天然只有 0.02 量级，绝对分数门槛会误杀全部分裂，使树退化为顺序分块。末级容量随语料量动态增长：`max(2, ⌊5·log₂N⌋)`（545 会话 → 45 条/末级）；此前固定 10 条会把 545 会话切成 118 个碎块，动态后为 27 个末级、语义更完整。同一门槛反向驱动**分类合并**（collapse_small_category_subtrees）：工作区目录往往只分到主题树的一小片，若某分类子树的会话总数不超过门槛，整棵子树就地收拢到该分类直挂会话——几个会话不必穿透与主题树同深的层级。合并不跨兄弟、不改变节点 id 与名称，收拢到子树总数不超过门槛的最高分类为止。

**5. 两次合并守边界。** 小于 `min_child = max(3, ⌈max_leaf/5⌉)` 的小簇并入质心最相近且合并后不超容的兄弟簇，无法安全合并的孤立小簇保留不硬并；兄弟簇质心余弦相似度 >0.62（`SESSION_TREE_SIBLING_SIM_MAX`）视为同一主题，合并后继续递归。前者消碎叶，后者消同层重复主题。

## 四、命名：兄弟对比式命名 + 熔断

聚类完成后，按**同层兄弟组**（而非逐分类）各调用一次 `SUMMARY_MODEL`：prompt 同时给出各组素材，要求返回 JSON 格式的互斥名称与可选 merges；仅当合并对象是末级兄弟且合并后不超容量才执行合并，响应不可解析时回退逐组命名。对比命名是治"名称趋同"的关键——逐分类独立命名时，LLM 看不到兄弟，5 个分类会各自叫出"Agents 管理"。

命名素材每个末级最多抽 12 个会话，每条含标题、首条用户消息、常见工作区、共享改动文件，使名称能携带项目与文件领域信息。内部节点由其子分类名命名，父级最多 4 个命名任务并发。

LLM 不可用时回退高频词命名，并用中文 n-gram 重叠拼接相邻词（重叠 ≥2 字直接恢复完整词；仅重叠 1 字时要求拼接结果本身存在于候选词，避免"件管理"式伪词）。命名连续失败 3 次触发熔断：后续命名直接采用回退名称，不再拖累外部服务故障期间的重建；一次成功即清零计数。

实测效果（545 会话线上树）：27 个末级分类零重名，仅 2 个名称同时包含 agents 与 runtime 两个泛词；出现"群聊消息处理""运行时网络与终端环境""文件变更与消息预览"等超越关键词堆砌的名称。

## 五、增量维护：所有路径共用一个漏斗

分类树不是一次性构建物——会话每天都在产生和删除。一致性规则：**无论自动还是手动，挂载走同一个漏斗**，这是用户明确要求并经测试钉死的契约。

- **新会话创建**：`on_session_created` 立即调用 `ensure_session_facts()`——工作区目录与月份节点即时上树，不依赖 LLM 标题或主题分类。
- **轮末自动压缩**与**手动"重新生成概要和记忆"**：最终都到达 `session_manager.update_index(generate_title=True, compression_updated=True)` → 标题生成 → `attach_session_to_category()`（主题单分类移动）→ `_apply_session_facts()`。后者是事实根的唯一入口：补工作区目录、补月份、把工作区副本中的"未分类"会话迁移到主题镜像路径（`_mirror_category_in_workspace`）。
- **会话删除与搬移**：`remove_session_from_tree()` 剪除空分类后与 `attach_session_to_category()` 挂载后都跑分类合并——删除使子树变小，低于门槛的链随即收拢；镜像副本被深挂载重新拆深后，合并步也会再次收拢（`_collapse_category_copies`，与构建期同一门槛同一函数）。
- **标签编辑**：`set_session_labels()` 整组替换 index.json 的 `labels`（前后端同一套分隔符语义：半/全角逗号与空白），`_sync_tree_labels()` 随即在标签根增删挂载；`_apply_session_facts()` 按 index 已有标签增量补挂，保证自动压缩与手动重生的挂载一致。
- **会话删除**：`remove_session_from_tree()` 从所有末级移除、剪除空分类并重算祖先计数；结构性根（终端、标签、历史）即使空也保留。

契约内容写在 `_apply_session_facts` 的 docstring 中，由 `tests/test_session_fact_roots.py` 强制：

1. **按根类型的不变量测试**——主题根中的每个会话必须同时出现在所有非终端根下。新增任何分类体系/森林根时，若挂载路径忘记补挂，测试直接失败。
2. **自动/手动等价测试**——同一会话分别经轮末自动压缩与手动重生成两条路径处理后，主题 leaf 路径、工作区副本路径、月份成员必须逐项相等。

今后新增分类体系的标准动作：在 `_apply_session_facts` 登记增量补挂逻辑，在不变量测试的根类型清单中登记新根类型。

## 六、接口与运维

**在线接口**

- `GET /v1/sessions/tree`：tree.json 缺失或版本低于 `TREE_VERSION` 且会话数 >5 时，经守护线程后台构建并返回 `building: true`，前端每 10 秒轮询直至完成；失败进入 30 秒冷却。
- `GET /v1/sessions?category=<id 链>`：按路径分页取会话。主题根与任意工作区目录下的分类副本都可查询，各副本按自身路径独立寻址，互不改写。
- `POST /v1/sessions/tree/terminal/layer{,/update,/remove}`：终端嵌套层增改删，详见 `docs/introduce-exec_cli-tool.md`。
- 标签：`POST /v1/sessions/{id}/labels` 整组替换会话标签；`POST /v1/sessions/labels/summarize` 生成标签聚合（概要/记忆/众数配置），落盘 `DATA_DIR/labels/<标签>.json`；`GET /v1/sessions/labels?label=` 读取聚合文档。`generate-title` 接受可选 `labels` 列表，与标题正交。

**标签聚合（`runtime/label_store.py`）**：合并该标签全部会话的 summary/memory（未生成者截取对话首尾各 1500 字），单会话素材 6000 字、总素材 60000 字封顶，交 SUMMARY 模型产出统一概要/记忆（不可用时降级为直接拼接）；配置取执行环境、工作区、模型、工具、AI代理在各会话中出现次数的众数。前端"生成新会话"把聚合概要/记忆按 system 消息写入 ChatPage（等同提示词模板"作为系统提示词"），并套用众数配置。

**CLI**（独立进程，无需重启服务）

```bash
python -m runtime.category_tree_builder --chats-dir chat_data   # 完整构建，回退命名
  --llm                      # 启用 SUMMARY 模型命名
  --refresh-facts            # 保留主题子树与既有命名，重建工作区/终端/历史事实根并归一化分类合并
  --classify-missing --llm   # 为未挂载会话用 SUMMARY 模型选既有末级分类，顺带补标题
  --dry-run                  # 只打印不写
  --force / --max-leaf-size N / --min-sessions N / --seed N
```

两个常见运维场景：升级森林版本后跑一次 `--refresh-facts`，既有 LLM 分类与命名原样保留，只补事实根；服务进程与 tree.json 脱节（旧进程挂载的会话缺工作区/历史条目）时，跑一次 `--refresh-facts` 或 `--classify-missing --llm` 即可批量补齐。

调参环境变量：`SESSION_TREE_DF_MASK_RATIO`（默认 0.35）、`SESSION_TREE_SIBLING_SIM_MAX`（默认 0.62）。

## 七、前端形态

侧栏顶部是一行模式图标（最近会话 / 主题 / 历史 / 工作区 / 标签）加独立靠右的终端入口，共用同一个树面板，不存在四根争抢树框高度；树中隐藏包裹根、直接显示顶层分类。最近会话不再是树根，而是会话 API 的整体分页列表（无条数上限）。工作区节点的子树展示该目录下的主题分类副本——只保留含目标会话的分支，未分类会话落"未分类"兜底节点。会话右键"所属目录"列出该会话在所有根下的完整路径，点击即切换到对应模式、展开祖先、选中末级并滚动到原会话。会话菜单的"设置标题与标签"在标题输入框下提供标签输入框；标签节点右键只有两个动作：生成概要和记忆、生成新会话。

## 八、线上实测（2026-11-21 v9 刷新）

551 会话全部挂载，membership 边 551 条，0 个多分类会话；标签根 3 个（人工标注已在使用）；主题 27 个末级（规模 1–45，满足容量规则）、156 个主题节点——内部子树都在门槛之上，合并对主题树是零操作；13 个执行环境节点、41 个工作区目录节点（Windows 盘符路径按原反斜杠风格展示），分类合并后目录下的副本分类节点共 81 个、其中仅 4 个内部节点：小工作区普遍只剩一层平铺分类，只有 340 会话的 agents 目录保留中间层级；终端根 12 个环境子节点、6 个嵌套子终端层；7 个月份节点。
